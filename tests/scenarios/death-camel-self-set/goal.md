# 死亡骆驼将自身变为里侧守备表示

## 用户原话（录制前）

> 开启一个新的决斗剧本录制，本次关注的点是怪兽区域盖放, 02326738的1效果将自身变成里侧守备表示，考察这个事件能否具备被agent笔记工具记录的可能

## Agent 整理的可核查目标

1. 用确定性双客户端录制，让操作方起手包含「死亡骆驼」（卡片密码 `02326738`，数据库与协议中的数值 ID 为 `2326738`）。
2. 操作方在自己的主要阶段召唤死亡骆驼，并发动①效果，使它在同一怪兽区格子由表侧变为里侧守备表示。
3. 分别核对双方视角的发动、表示形式变化事件，以及变化前后该怪兽区格子的快照。对方当前快照若隐藏卡片 ID，不得用操作方日志补足；只用对方自己曾实际看到的公开信息评估是否可以维护“这张盖放怪兽曾是死亡骆驼”的推断。
4. 双方完成权威终局，生成动作剧本并回放。候选场景应断言位置变化与对方最终里侧怪兽状态；如事件缺少卡片身份，明确说明需由历史表侧状态与位置关联推断，且位置复用后需重审。

## 建议操作与录制约束

- 操作方建议使用 `deck/test/3.ydk`，其主卡组首张是 `2326738`；另一方可使用 `deck/test/test.ydk`。录制器会保存双方实际提交的牌组，以日志为准。
- 操作方先攻，通常召唤死亡骆驼后，在主要阶段发动其①效果。看到它变为里侧守备表示后，可结束回合并由任一方投降，以便双方收到终局。
- 房间为单局 1v1、起手 5 张、LP 8000、每回合抽 1 张、无时间限制，必须开启「不洗牌」；「不检查卡组」可开可关。

## 录制前待核查项

- 当前客户端已有 `position_changed` 事件，包含玩家、区域、格子序号及前后表示形式，但事件自身没有卡片 ID。需要核对效果结算时是否确实发出该事件，及同一视角先前是否确实见过该位置的表侧卡身份。
- 当前 `read_zone_note` / `write_zone_note` 仅支持对手手牌与 `spell` 魔陷大区；`monster` 尚无独立笔记。录制后评估是否仅需扩展笔记区域，还是客户端事件还缺少必要信息。

## 录制后核查结论

- 录制 `62e7b8fbe66b4bccab6db404a9b3c117` 已完成，清单与原始草稿自动回放均为 `validated`。实际由 Guest 猜拳获胜并先攻，使用 `deck/test/3.ydk` 召唤死亡骆驼、发动①效果；Host 在第二回合投降，Guest 获胜。Host/Guest 是客户端进程角色，不随先攻选择改变。
- Host 在怪兽区序号 0 表侧攻击表示时的本视角快照看到 `card_id=2326738`；之后 Host 观察到该卡发动效果及序号 0 的 `position_changed(face_up_attack -> face_down_defense)`。结算后的 Host 快照同一格 `known=false`；Guest 自己的快照仍 `known=true`。
- 因此客户端协议已提供“曾见身份 + 同一位置变为里侧”的证据，可以供 Agent 写一条带不确定性标记的推断笔记。当前笔记工具拒绝 `zone="monster"`，这是服务端工具范围缺口，不是这次客户端事件缺失。位置被其他卡复用或该卡离位后，推断需要重新审查。
- 编译器生成 Guest 4 步、Host 0 步，无同形候选序号覆盖。候选剧本额外断言双方的效果发动、表示变化，以及 Host 最终 `known=false`；验证结果见 `README.md`。
