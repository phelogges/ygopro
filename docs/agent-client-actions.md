# 客户端执行用户与 agent 动作

人工操作最终都会落到以下既有接口：

1. `DuelClient::SetResponseI`：写入单个 32 位整数响应；
2. `DuelClient::SetResponseB`：写入选卡下标等字节序列；
3. `DuelClient::SendResponse`：清理当前选择 UI，并将响应发送到单人模式或
   `CTOS_RESPONSE` 网络包。

主要阶段和战斗阶段的整数响应通常把候选索引放在高 16 位，把动作类型放在低
16 位。例如：`(1 << 16) + 1 = 65537` 表示第二个候选的特殊召唤。是/否、选项、
表示形式和连锁等提示各有自己的整数值。选卡响应则为：第一个字节是卡片数量，
后续字节是服务端给出的选择序号。

`AgentClient::Poll` 在主线程读取远端回复；它不会直接执行任意字节，而是检查：

- 回复的 `request_id` 与当前未完成请求一致；
- 当前引擎消息仍与请求生成时相同，避免迟到回复影响下一次选择；
- `integer.value` 位于当次 `integer_choices`；
- `cards.indices` 不重复、数量满足最小/最大限制，且全部属于 `card_choices`；
- `cancel` 只在引擎允许取消时生效。

通过验证后，agent 回复复用完全相同的三步客户端响应路径。当前没有 agent 或
连接/握手失败时，采集模块绝不发送对局响应，人工界面保持可操作。
