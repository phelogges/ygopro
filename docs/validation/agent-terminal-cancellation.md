# 终局时取消 Agent 决策

## 现场证据

在本地配置档最后一场决斗的客户端日志中，`MSG_WIN` 于 01:42:11 到达，报告本方获胜；服务端 SQLite 中当前决策 `215:137` 从 01:42:03 运行至 01:42:39，仍签发并提交了动作。直到 01:43:41 收到 `STOC_DUEL_END`，客户端才同步 `duel_ended`（事件 558）。其间录像保存交互使 `STOC_DUEL_END` 晚于胜负消息。两端原有实现都没有用 `MSG_WIN` 取消正在运行的模型任务。

## 修复边界

- 客户端在收到完整 `MSG_WIN` 报文时，先记录可见终局事件并撤销当前 Agent 请求，然后继续原有胜利动画与录像流程。终局事件通过既有 `/v3/sync` 持久传递。
- Agent 服务持久接收终局事件后，取消本局正在执行的模型与工具任务；此局后续决策视为旧提示。已经提交给游戏服务端的动作不会被追溯撤回。`STOC_DUEL_END` 仍可重复触发客户端清理，但不重复生成终局事件。
- 不修改游戏服务端、CTOS/STOC 协议或 `ocgcore`。
