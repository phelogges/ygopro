# Agent 对手已观察信息认知笔记契约 v1

> 状态：现行 Agent 推断笔记契约。覆盖对手手牌、魔陷区和主怪兽区 0–4 号格；笔记不是权威快照。旧路径 [agent-hand-note-v1.md](agent-hand-note-v1.md) 仅作迁移指引。工具接入与共同执行语义见[工具契约](agent-tools-v1.md)。

## 事实边界

客户端的可见快照和有序事件仍是本方视角的观察事实。对手手牌在当前快照中只显示数量；曾展示给本方的卡片 ID 通过 `cards_revealed` 事件进入历史。对手魔陷区的盖卡在当前快照中仍为 `known=false`，即使先前曾公开展示。魔陷区展示事件可含客户端实际收到的格子 `sequence`，与 `card_set` 的位置关联；不得从另一客户端日志补齐。`shuffle_message_observed` 表示观察到洗手，不表示展示过的卡片从手牌消失。对手后来打出同名卡，也不能仅凭卡名断定手中没有其他副本。

Agent 可以对对手手牌、魔陷区和主怪兽区分别维护中文自然语言的**推断说明**；主怪兽区按序号 0–4 独立维护。说明与快照、事件分开存储，不改变 `known`、`card_id` 或隐藏卡的序号；程序不根据展示、洗牌或移动事件自动增删结论。魔陷区说明可按格子写明曾展示的卡片及依据；主怪兽区说明可记录先前见到的表侧身份与随后同格变为里侧的事件。卡片离位、重新盖放或位置复用后，应由 Agent 根据新事件修订，不能把旧结论当作当前事实。说明中不得把计划中的动作写成已发生事实。

## 范围与工具

存储和工具按客户端 `session_id`、`duel_id` 与本方视角隔离。接口接受 `player=1, zone="hand"`、`player=1, zone="spell"`，或 `player=1, zone="main_monster", sequence=0..4`。主怪兽区五个格子各有当前说明与修订历史；序号 5、6 的额外怪兽区、场地区及其他区域仍不开放专属笔记。手牌和魔陷区调用不得带 `sequence`。

- `read_zone_note(player=1, zone, sequence?)`：读取指定区域或主怪兽区格子的当前说明、修订 ID、时间、依据事件 ID、最近一次修订时已接收的事件上限和是否又有新事件；尚未建立时返回 `status="unwritten"`，不暗示该区域为空。省略参数仍默认对手手牌。
- `write_zone_note(player, zone, note, evidence_event_ids, sequence?)`：由 Agent 整段替换指定区域或格子的说明。`note` 是 1–2000 字符的非空自然语言说明，当前提示要求使用中文；`evidence_event_ids` 为 1–20 个不重复的本视角事件 ID。服务端只核对引用事件确实存在于当前决策已确认的事件前缀，不判定自然语言推论的正确性。写入失败返回工具错误并保留旧版。

例如观察到同一魔陷区序号 3 的 `card_set` 与 `cards_revealed(card_id=89023486)` 后，Agent 可以写入“对手序号 3 盖卡曾展示为原罪宝－蛇眼；离位后需复核”，并引用这两个事件在**本局本视角**的实际 ID。不能把示例或另一局录制中的事件 ID 直接复用。

对手主怪兽区序号 0 的死亡骆驼例子中，本方先见到表侧身份，随后 `effect_activated(card_id=2326738, location=4, sequence=0)` 与 `position_changed(location=4, sequence=0, face_up_attack -> face_down_defense)` 均在本视角事件历史中。Agent 可以在 `zone="main_monster", sequence=0` 写入“该格的里侧怪兽曾是死亡骆驼；离位后需复核”，引用本局实际事件 ID。`position_changed` 自身不含卡片 ID；未观察到的身份不得补入说明。

写入工具由服务端直接执行，不开放任意文件系统写入或在 CodeMode 中执行。手牌修订继续使用原有 `hand_note_revision` 记录，魔陷区修订使用 `spell_note_revision`；主怪兽区每格使用 `main_monster_note_revision_<sequence>`，旧版保留。记录包含区域、可选格子序号、正文、事件引用、修订时的 `state_version` 与 `observed_ack_event_id`。说明写入不会推进权威快照版本或事件确认序号，也不代表本次决策动作已经执行。

## 模型输入与人类查看

每次决策的模型输入包含本轮 `new_events`、净场面变化、当前提示及 `opponent_hand_note`、`opponent_spell_note`，还有按序号排列的五项 `opponent_main_monster_notes`。若最近一次修订后已有新事件，给出 `newer_events_exist=true`；这只提示重新审视，不自动宣告说明失效。Agent 可以用 `event_history` 核查证据，并自主调用写入工具修订；上下文压缩不删除事件日志和说明版本。

网页在该客户端视角下标注“Agent 推断”，分别展示手牌、魔陷区与主怪兽区五格的当前说明、事件引用、修订时间和版本历史。人类可见的说明仍只来源于同一客户端视角，不与对手客户端的离线录制信息合并。

## 验证与后续

`duel-002` 的本地场景断言检查 Host 收到“旋风、绚岚之米克拉展示”及后续洗手事件；快照仍隐藏对手手牌 ID。录制 `6aba04db61ae42fc8301a5165b60bb75` 验证对手盖放与展示「原罪宝－蛇眼」的事件都含魔陷区序号 3，而 Guest 当前快照保持卡片身份未知。模型工具测试覆盖两区独立写入、下一决策读回、后续事件提示、重启恢复、视角隔离及无效事件引用。

录制 `62e7b8fbe66b4bccab6db404a9b3c117` 已证明，观察方能先看到死亡骆驼的表侧身份，再收到同格从表侧攻击变为里侧守备的 `position_changed`；当前快照随即隐藏身份。场上怪兽发动事件新增本方可见的 `sequence` 后，该场景再次双端回放通过。主怪兽区笔记已按 0–4 号格独立实现；位置复用、离位后的模型主动修订仍需实战验证。录制 `5da8960aff234c089e3d576bfde4cf7e` 已证明场地区序号 5 的盖放和展示事件可以关联；对手**场地区**独立笔记仍待实现。当前快照的 `monster` 同时包含额外怪兽区（序号 5、6），`spell` 同时包含场地区（序号 5）及其他格子；笔记名称不改变这些权威快照的大区定义。已知卡组顶及其他“先公开后隐藏”的区域知识也仍为 TODO，需要具体双端录制核对消息、位置关联和后续失效条件。
