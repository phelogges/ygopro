# Agent 对手手牌认知说明 v1

## 事实边界

客户端的可见快照和有序事件仍是本方视角的观察事实。对手手牌在当前快照中只显示数量；曾展示给本方的卡片 ID 通过 `cards_revealed` 事件进入历史。`shuffle_message_observed` 表示观察到洗手，不表示展示过的卡片从手牌消失。对手后来打出同名卡，也不能仅凭卡名断定手中没有其他副本。

Agent 可以维护一段中文自然语言的**推断说明**。它与快照、事件分开存储，不改变 `known`、`card_id` 或隐藏卡的序号；程序不根据展示、洗牌或移动事件自动增删说明中的结论。说明中不得把计划中的动作写成已发生事实。

## 范围与工具

存储和工具按客户端 `session_id`、`duel_id` 与本方视角隔离。接口保留 `player`、`zone` 参数，v1 仅接受 `player=1, zone="hand"`，即对手手牌。其他隐藏区以后依据实际双端录制单独设计。

- `read_zone_note(player=1, zone="hand")`：读取当前说明、修订 ID、时间、依据事件 ID、最近一次修订时已接收的事件上限和是否又有新事件；尚未建立时返回 `status="unwritten"`，不暗示对手手牌为空。
- `write_zone_note(player, zone, note, evidence_event_ids)`：由 Agent 整段替换说明。`note` 是 1–2000 字符的非空自然语言说明，当前提示要求使用中文；`evidence_event_ids` 为 1–20 个不重复的本视角事件 ID。服务端只核对引用事件确实存在于当前决策已确认的事件前缀，不判定自然语言推论的正确性。写入失败返回工具错误并保留旧版。

写入工具由服务端直接执行，不开放任意文件系统写入或在 CodeMode 中执行。每次成功写入向本地 SQLite 追加 `hand_note_revision`，旧版保留；记录包含正文、事件引用、修订时的 `state_version` 与 `observed_ack_event_id`。说明写入不会推进权威快照版本或事件确认序号，也不代表本次决策动作已经执行。

## 模型输入与人类查看

每次决策的模型输入包含本轮 `new_events`、净场面变化、当前提示和简短的当前手牌说明。若最近一次修订后已有新事件，给出 `newer_events_exist=true`；这只提示重新审视，不自动宣告说明失效。Agent 可以用 `event_history` 核查证据，并自主调用写入工具修订；上下文压缩不删除事件日志和说明版本。

网页在该客户端视角下标注“Agent 推断”，展示当前说明、事件引用、修订时间和版本历史。人类可见的说明仍只来源于同一客户端视角，不与对手客户端的离线录制信息合并。

## 验证与后续

`duel-002` 的本地场景断言检查 Host 收到“旋风、绚岚之米克拉展示”及后续洗手事件；快照仍隐藏对手手牌 ID。模型工具测试覆盖写入、下一决策读回、后续事件提示、重启恢复、视角隔离及无效事件引用。

检索后盖放、已知卡组顶及其他“先公开后隐藏”的区域知识为 TODO。待取得具体双端录制，再核对客户端实际收到的消息、位置关联和洗牌后的失效条件；本版不推断这些情况。
