# 二期 Agent 服务设计

> 状态：现行总设计。协议格式以 [HTTP v3 契约](../contracts/agent-http-v3.md)为准；状态细节见[现行状态设计](agent-state.md)，Codex 专属取舍见[Codex 后端设计](agent-codex-backend.md)。

## 目标与范围

在一期可见状态和语义动作契约上，实现 `agent_server/` 中的完整本地 Agent 服务。客户端在配置启用时启动独占子进程；原有 Pydantic AI 后端调用 OpenAI 风格 Responses 端点，通过本地 Monty 代码沙盒和受限工具分析对局，输出可校验的语义动作。新增可选 Codex 后端的隔离、工具和运行时要求见 [Codex Agent 后端设计](agent-codex-backend.md)。首版中文、单局 1v1；人工完成房间和卡组操作。游戏服务端、CTOS/STOC、`ocgcore` 和卡片脚本不改。macOS 先实现，Windows 最后构建验证。

正式通信以 [HTTP v3](../contracts/agent-http-v3.md)为准；一期 v2 测试服务保留。

## 组件

```text
gframe AgentController ── HTTP v3 ── agent_server
  可见快照 / 事件 / 候选          │
  查询执行 / 动作提交            ├─ 持久事件与状态检查点
                                ├─ agent_sdk 状态差异与动作校验
                                ├─ DuelTools 共用工具执行层
                                │    ├─ 规则书与卡片数据库
                                │    ├─ 当前场面 / 分页历史
                                │    └─ 受限计算
                                ├─ Pydantic AI Responses Agent ─ 本地 Monty CodeMode
                                ├─ Codex Agent ─ 单个本地 MCP 服务
                                └─ 本机只读人类视图
```

一个客户端对应一个服务进程和一个可见视角。配置位于发布主目录 `.agents/`；`config.toml` 是默认档，同目录下可放其他具名档。开发时项目根目录视为发布主目录。客户端选定配置档后启动固定端口的子进程；端口占用或就绪令牌不匹配时停止自动接管。API 密钥只通过配置中指定的环境变量读取，不写入 Git、命令行或日志。

## 状态与事务

客户端每个真实决策发送完整本方可见快照、未确认的有序事件、提示和候选。服务先用 `agent_sdk` 验证，再将原始观察、状态版本、事件确认及净差异持久化；确认必须发生在事务提交后。服务使用追加式事件记录与周期状态检查点，而不在每个提示重写整局。重传以 `(session_id, duel_id, prompt_id, state_version)` 和请求指纹去重。服务重启从完整日志与检查点恢复已确认事实；损坏或缺口不得伪装成完整历史。

权威镜像只有客户端可见状态；模型摘要、计划和卡片解释放在独立非权威命名空间。模型读状态、历史与人类页面共用同一查询层，不维护第二份事实。跨两名玩家的轨迹只在离线验证中合并。

## 模型运行

`OpenAIResponsesModel` 配置 `base_url`、模型名和密钥环境变量。启动时对真实端点验证 Responses、工具调用和结构化输出能力；未配置端点时可运行离线假模型测试模式。默认 `store=false`，不使用供应商保存的会话链；本局模型消息由服务本地持久管理。模型输出受 Pydantic 校验的语义意图和简短中文说明，再由 `agent_sdk` 翻译合法动作，客户端复核后提交。

初始系统指令：以赢得当前单局为目标；依据合法候选、本方可见事实、卡片资料与规则决策；区分观察、推测和未知；需要时使用工具；不修改卡组、房间或游戏协议。指令按版本管理，后续可优化战术内容，但配置不能覆盖工具权限和可见性边界。

系统指令存放于发布主目录 `.agents/prompts/duel_system.md`，使用 UTF-8 Markdown。服务启动时读取一次；首次接管每局时保存指令正文及哈希，后续该局即使服务重启也沿用已保存版本。指令保持通用，不使用实时模板变量；提示中的场面、合法候选、约束、预算和动作格式由程序按当前请求提供。卡组专用用法指南暂列 TODO。

客户端在人工选定并实际提交卡组后，从该提交捕获本方主卡组、额外卡组和备牌清单。v3 首次决策请求必须附带 `deck_manifest`，按卡片 ID 与张数表达无序清单；同一 `(session_id, duel_id)` 持久化一次，之后请求省略。首次赛前模型上下文收到从 `cards.cdb` 生成的主卡组和额外卡组紧凑目录（ID、张数、卡名、类型，不含效果文本）；备牌仅保存，不进入本期决策上下文。Agent 可通过 `own_decklist` 工具重新读取自己的目录。没有清单时拒绝该局首次决策并交还人工；已保存清单与重传值冲突时拒绝请求。

每个决策默认输入本轮有序新事件、快照净差异、当前提示及完整合法候选。可配置 `context_window_tokens`、压缩触发比例和目标比例。压缩只处理模型上下文：先用 Harness 清理旧工具结果，仍超预算时用模型摘要旧对话，失败时用完整轮次滑动窗口兜底。摘要注明覆盖范围、单独保存，不取代完整事件日志。摘要调用计入模型请求和总期限；时间不足时直接使用确定性窗口。当前提示、候选和本轮工具结果不可裁剪。旧版笔记工具退出后，缺少当前工具集版本的已保存模型会话不再恢复；升级后的首次决策重建上下文并重新提供该版本的完整已确认快照。旧事件和模型轨迹仍保留在数据库中。

## 工具与沙盒

两种 Agent 后端遵循“业务能力共用、接入层分别适配”的约定。规则与卡库查询、牌表、权威场面和事件均由服务端同一套资源、状态与业务实现提供；Pydantic AI 用 `@agent.tool` 注册，Codex 用单个本地 MCP 服务暴露，再转发到服务端执行。工具描述和参数格式属于各接入层；权限、可见性、状态版本和预算校验在服务端代码中落实，并通过两端入口验证，不能仅依赖模型指令。新增或修改共用能力时，检查两端的工具名称、参数、说明、结果与测试；后端专属能力应明确标记，不要求伪装成完全相同的工具清单。系统指令只描述决策原则，不作为工具注册表或参数文档。

实现中，`agent_server/duel_tools.py` 定义后端无关的 `DecisionDeps` 与 `DuelTools`：决策上下文负责期限和工具次数，工具执行层统一调用技能资源、场面存储、事件和受限十进制计算，并记录批量卡片查询指标。保留的 HTTP v3 客户端查询协议仍有独立预算，但不作为模型可见工具。`model_agent.py` 的注册函数只转发模型可见的方法；`codex_mcp_bridge.py` 校验 MCP 入参后也调用同一执行层。框架要求的工具 schema、描述和异步转发仍由各自接入层维护，不把业务查询逻辑复制到接入层。Pydantic AI 的 Monty CodeMode 另外允许在受限 Python 表达式中直接做计算，这属于框架执行方式，不构成不同的业务计算规则。

- 规则工具只读取发布主目录 `.agents/skills/ocg-rulebook` 的 `SKILL.md` 与白名单参考文件，按主题加载。
- 卡片工具只读取 `.agents/skills/ygo-card-db` 的实现和发布主目录 `cards.cdb`，支持单卡 ID 查询、批量完整详情 `cards_by_ids` 和有数量上限的关键词检索；批量 ID 数上限可配置，默认 12 个不同 ID。服务核对与客户端的数据库哈希。工具轨迹记录批次 ID 数、返回字节数和耗时。
- 临界预算保护为实验性配置：默认在剩余 2 次模型请求或 20 秒时（任一条件满足）进入最终化阶段，移除全部非最终输出工具，只允许提交最终动作；配置为 0 可关闭。它不提供确定性动作回退，也不替代期限和预算硬限制。
- 状态工具读取本视角指定版本的场面、区域、卡片和分页事件历史，返回版本与事件范围。
- 曾展示后重新隐藏的卡片身份由 Agent 结合当前镜像与本方 `event_history` 自主判断；不自动写入隐藏区身份，也不单独保存模型撰写的区域笔记。旧版笔记只在人类页面保留历史只读视图。
- Agent 通过 `current_state`、`zone_state`、`card_state` 和 `event_history` 查询服务端已确认镜像；`inspect_zone`、`inspect_card` 客户端往返仅为现存协议兼容和诊断保留，返回值必须等于冻结快照，当前不向模型暴露。
- CodeMode/Monty 只在本机执行受限 Python 子集，不配置远程 worker、文件挂载、OS 访问、Shell 或网络。仅明确列出的只读工具可在沙盒代码中调用；宿主工具再次核验会话、可见性、预算和结果大小。

同一提示默认最多 3 次无效结构化输出或非法意图尝试、8 次模型请求、24 次宿主工具尝试、60 秒总期限，均可配置。保留的客户端查询协议默认限 4 次，不计入常规模型工具集。摘要请求包含在模型请求预算中。模型可获知剩余预算，但由程序执行硬限制。临界预算保护的默认阈值另见上文。网络故障、历史不完整、状态冲突和总期限届满直接交还人工，不静默选择动作。

## 查询状态机与恢复

服务端接收决策后运行模型；正常模型工具直接读取已确认镜像。保留的客户端查询协议在被内部测试或兼容调用时挂起决策并返回 v3 `kind=query`。客户端检查提示仍有效并执行只读查询，再 POST 结果；服务继续处理，可再次查询或返回 `kind=action`。同一决策只允许一个待处理查询，所有中间阶段有不透明 ID 且幂等。动作发出后客户端发送 `submitted`、`stale_prompt` 或 `rejected` 回执。服务收到 `submitted` 也不把它解释为游戏服务端已执行。

HTTP 结果不明时可原样重传，服务返回当前阶段而不重复模型执行。服务崩溃或提示过期时交还人工；F10 恢复接管将重新启动服务，核对已确认状态和事件，再为新提示决策，不恢复中断的模型栈。客户端人工期间继续采集可见事件。

## 人类视图与发行

服务同进程提供本机只读 API 和简洁浏览器页面，使用与客户端不同的只读令牌，展示单方已确认场面、事件、净差异、提示、决策、工具查询及动作提交回执。快照和事件的更新时间分别标示；无决策时的 `/v3/sync` 不声称已刷新整场。

发行目录包含客户端资源、独立 Python 服务可执行程序 `agent-server`、由 `.agents/config.example.toml` 生成的 `.agents/config.toml`、两个纳入 Git 的运行时 skill、根目录 `cards.cdb`。发布脚本检查 skill 和数据库存在且哈希匹配后复制；根卡库继续由用户本地维护，不纳入 Git。先交付 macOS 可复制目录与版本化压缩包，Windows 最后同布局验证；签名、公证与安装器不在本期。

## 验证

用确定性假模型与本机假 Responses 端点覆盖协议、牌表绑定与重启恢复、批量卡片查询、临界预算保护、压缩、技能查询、隐藏信息、重传、超时、故障与重启；用既有复杂场景执行双客户端无头及 GUI 回归。配置样例不含密钥。真实端点由用户在其他测试完成后提供，再做至少一局冒烟测试；各验证路径单独报告，未执行不写成通过。牌表目录的具体战术指南待后续按构筑补充。
