# 可视化双客户端场景验证

> 状态：现行设计。适用于 GUI 场景回放；具体运行方式见[场景回放指南](../guides/scenario-replay.md)，执行证据见[验证总览](../validation/README.md)。

## 目标与边界

在现有固定牌序 LAN 双客户端场景验证上增加 `--gui` 模式，显示 Host 和 Guest 两个原生客户端窗口，运行同一 YAML 剧本、语义动作校验与终局断言。默认每个明确脚本动作增加 1 秒观看时间；未列入剧本的可选提示自动放弃，不增加等待。无 `--gui` 时沿用无界面回归的速度和进程生命周期。游戏服务端、`ocgcore`、卡片脚本及 CTOS/STOC 协议不变。

## 时序

客户端收到游戏消息时，现有 `ClientAnalyze` 及 `WaitFrameSignal` 先推进原有动画，随后才请求下一动作。默认 HTTP v3 下，Host、Guest 各有独立离线 Agent 子服务，二者从共享脚本协调器取得本局 YAML 动作；`--protocol v2` 使用历史测试服务。脚本协调器按决策串行提供步骤，在返回每个明确动作前等待 `--step-delay` 秒；赛前猜拳和先后攻选择也属于明确动作。自动放弃的可选提示不等待。投降在最终可见场面满足断言后再等待一次 `--step-delay`。因此等待是动画处理完成后的额外观看时间，不通过阻塞客户端绘制线程实现。

## 窗口与进程

GUI 客户端使用正常图形驱动并临时关闭快速动画；不保存运行时配置。窗口标题标出角色，屏幕宽度足够时并排放置，空间不足时交由系统摆放。测试结果或错误写入原有报告后，命令行返回，窗口留在当前画面供人工查看，直到手动关闭。场景检查点通过本地信号停止自动决策并保留窗口；终局由现有胜负消息完成。若用户中途关闭窗口，验证按客户端提前退出报错。保留的窗口不再依赖场景服务进程。

测试入口绕过主菜单按钮直接创建 LAN 对局，因此启动时关闭主菜单。Agent 提交动作时，由客户端校验并发送既有协议响应，同时清除该提示弹窗的淡入、淡出队列，恢复窗口尺寸并关闭弹窗；否则渲染循环可能在下一帧将弹窗重新显示。这里不合成鼠标点击事件。

## 超时与验证

`--step-delay` 仅随 `--gui` 启用，默认 1 秒，允许 0～10 秒。测试总超时自动增加脚本动作数乘延迟及投降展示延迟，单次 HTTP 决策超时独立覆盖允许的最大延迟。历史 GUI 场景已用 `duel-001`、固定起手和召唤连锁场景验证动画、窗口保留、报告及错误路径；默认 HTTP v3 的 GUI 路径仍需单独实测，不能用已有无头 v3 报告替代。Windows 验证按项目顺序留到最后。
