# Agent 可观测性设计

## 背景与目标

现有 `/view` 需要手动刷新，主要给出已完成决策后的原始 JSON。复杂对局中，人需要看见每次提示之后模型请求、供应商实际返回的推理内容、工具往返、动作校验和客户端回执的先后关系；模型超时或进程退出时，也要保留此前已发生的步骤。本设计扩展二期服务的人类视图，不改变客户端、决斗服务端或 CTOS/STOC。接口形状以[可观测性契约](../contracts/agent-observability-v1.md)为准。

## 边界

- 一个配置档对应 `.agents/data/<profile>/` 中独立的数据库和查看令牌。`host`、`guest` 与默认 `config` 的页面、事件、导出和清理严格按档隔离；对局中的两个页面不合并视角。
- `agent_server` 自行提供本机静态 HTML、CSS 和原生 JavaScript，不依赖 Node、外部 CDN 或客户端 GUI。页面通过 `fetch` 携带 Bearer 令牌读取 JSON 与 SSE，令牌不放入 URL。
- 推理区域只展示供应商实际返回且允许显示的文本或摘要，标明 `provider_reasoning` 来源，并以 `form: summary|text` 标注实际内容形态。模型生成的简短决策理由单独标为 `model_decision`。端点不返回推理内容时显示“供应商未提供推理内容”，决斗继续；不能推断或编造原始思维链。
- 本地观察轨迹包含当时本方可见的私有信息。页面仅监听回环地址，并以独立于客户端决策令牌的授权访问。密钥、令牌、供应商加密推理和内部签名不得进入轨迹、页面或导出。

## 数据流

```text
客户端提示 ──► 决策会话 ──► 模型流式响应 ──► 工具 / 校验 / 动作
                    │               │                    │
                    └──────► 追加式 trace_events ◄────────┘
                                   │
                          分页 JSON / SSE 游标
                                   │
                           静态对话式页面
```

一次游戏提示构成一个大轮，以 `turn_id = "<prompt_id>:<state_version>"` 标识，并始终与 `session_id`、`duel_id` 联合使用。每次模型响应分配不同的 `response_id`，包含重试、压缩请求和工具往返后的继续响应。事件在档内有严格递增的整数 `id`，持久化字段为 `kind`、经白名单处理的 `payload` 和 `created_unix_ms`，可带对应的 `turn_id` 与 `response_id`。页面按大轮组织多条模型消息，把工具调用和结果放在对应响应下；点击消息展开输入输出摘要、耗时、校验及原始安全字段。场面与历史作为独立页签，并标注快照版本与事件截止点，避免把旧快照误称为实时场面。

发起模型请求、工具调用、工具返回、错误、动作验证与回执在出现时立即落盘。流式文本可按短时间或大小阈值批量持久化，页面按已提交事件实时追加；未提交的内存片段不宣称可恢复。每次响应有开始、内容更新、完成或中断状态。进程崩溃后，重启扫描未终结响应并标为“中断”，保留已持久化片段，不恢复模型栈或重复提交动作。页面断连后从最后收到的事件 `id` 补拉，再继续流式接收；事件仅追加，已有内容的修订也以新事件表达。

模型消息采用显式字段白名单与递归大小、深度限制。仅保存可展示的文本、推理摘要、工具名称及安全参数摘要、可见的工具结果、结构化意图、验证结果、耗时与供应商状态。不得直接序列化 SDK 原始消息对象；特别排除 `signature`、`provider_details`、加密推理内容、认证头、环境变量和令牌。供应商是否提供推理内容在 UI 中逐响应标识；无法区分来源的扩展字段不进入展示或导出。

## 查询、管理与发行

分页时间线与 SSE 都以同一持久事件 ID 为游标，避免页面打开后漏掉事件。SSE 发送已提交事件与心跳；断连按游标重连，浏览器渲染基于 ID 去重。对于过期或已清理的游标，客户端重新请求当前分页，不假设历史完整。服务器为慢消费者设置缓冲上限，断开后允许重连，不阻塞决策。

人类页面可按对局导出 JSON，包含本视角可见状态、时间线、工具轨迹、实际收到的推理摘要和元数据，导出时再次执行相同白名单。卡名仅由发布主目录 `cards.cdb` 补充在视图层，保留 ID，不修改权威轨迹和给模型的协议。手动删除通过 `agent-server --delete-duel` 命令指定已结束对局，不开放 HTTP DELETE，viewer 令牌始终只读；自动清理默认保留最近 30 天且本档持久 `payload` 的逻辑字节数不超过 2 GiB，先删最早的已结束对局。正在进行或结束状态不确定的对局即使超过容量上限，也不自动清理。

`agent-server --view-only --config <profile> --port <port>` 只打开该档历史，不检查模型端点、不执行决策，指定端口被占用即报错。遗留 `.agents/data/state.sqlite3` 不猜测所属视角，只能通过显式遗留只读入口查看，不迁入任一档，也不参与默认清理或导出。静态资源进入独立服务可执行程序和 macOS 发布包；Windows 最后做同布局验证。

## 风险与验证

- **信息边界**：以两档交叉请求、隐藏卡、密钥和供应商扩展字段构造测试，断言无越权或泄露。
- **实时完整性**：模拟多次响应、工具往返、推理摘要片段、无摘要、超时、进程中断、SSE 断线重连和慢消费者；比对 UI 顺序与数据库事件 ID，确保未完成消息有明确标记。
- **持久与保留**：模拟重启、导出、手动删除、到期和容量清理；验证只删已结束对局，旧根数据库保持只读。
- **发行**：从独立 macOS 包运行完整页面与 `--view-only`，确认静态资源、卡名补充和配置档隔离；真实端点的推理摘要行为在用户提供端点后单独验证，不能由假端点测试代替。
